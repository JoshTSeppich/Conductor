## I — Data Path (End-to-End)

```
PTY stdout chunk
  → consoleController.addStdoutObserver (ConsoleIpcController)
  → registerTileTokenScraper (tile-token-scraper.ts)
      stripAnsi(/\x1b\[[0-9;]*[mGKHFJA-Za-z]/g)
      extractLastTokenCount(/([0-9]+) tokens/g — last match)
      500ms per-session debounce (Map<sessionName, {timer, tokensUsed}>)
  → mainWindow.webContents.send('workstation:tile-token-update', { sessionName, tokensUsed })
  → preload.mts contextBridge: onTileTokenUpdate — ipcRenderer.on + cleanup removeListener
  → workstationBridge.onTileTokenUpdate (WorkstationBridgeShape optional subscription)
  → TileGridApp useEffect → setSessions updater → session.tokensUsed
  → TileGrid → Tile → TileHeader → token meter fill bar
```

All five pipeline stages are independently tested. The fill bar rendering was pre-existing (MB-T15); §C.5 adds only the data plumbing.

## II — Spike Findings (Pre-Ticket)

Three-substrate live capture (SHA `ef2dd3d`, ADR at `docs/coordination/spike-c5-pty-scrape-2026-05-10.md`):

| Substrate | Token count captured | Regex match |
|---|---|---|
| claude-sonnet-4-6 | 24,220 | `[0-9]+ tokens\n` |
| claude-opus-4-7 | 33,863 | `[0-9]+ tokens\n` |
| claude-haiku-4-5-20251001 | 43,514 | `[0-9]+ tokens\n` |

All three substrates use plain integer (no commas) in the raw PTY status bar line. The `[0-9]+` pattern is stable across substrates.

**ANSI gap:** Spike used `tmux capture-pane -p` (ANSI-decoded). Raw PTY chunks from `addStdoutObserver` contain ANSI CSI sequences. Strip required before regex application. Fix: `/\x1b\[[0-9;]*[mGKHFJA-Za-z]/g`. Filed as `MB-F-SPIKE-C5-ANSI-GAP` Tier 2 at `b8fe0d0`.

## III — Implementation Notes

### WB1+WB2 — tile-token-scraper.ts

`IConsoleBroadcaster` interface (structural injection pattern) mirrors `pty-stream-relay.ts`. Accepts any object with `addStdoutObserver` — decoupled from `ConsoleIpcController` concrete type; test fixtures pass a fake broadcaster.

`extractLastTokenCount` uses `TOKEN_RE.lastIndex = 0` reset before each call — safe for module-level RegExp with `/g` flag. Extracts the last match in the chunk (the status bar token count is the rightmost occurrence; earlier matches in output body are discarded).

Debounce Map stores `{ timer, tokensUsed }` keyed by sessionName. Cleanup (`dispose()`) clears all pending timers and the Map. Per-session independence verified by probe-01 test 7.

### WB3+WB4 — model-context-windows.ts

Static lookup table; all three active v3.5 substrates → 200,000 tokens. `DEFAULT_CONTEXT_WINDOW = 200_000` fallback for unrecognised model strings. Degrades gracefully for future model releases.

**[KNOWN] Dead-export finding:** `getContextWindow` is exported and tested (6 probes, 6/6) but is not imported by any production source file. `tile-header.tsx:139` has `tokenBudget = 200_000` as the default prop value — this coincidentally equals `getContextWindow(any-current-substrate)`, so the fill bar renders correctly for all current substrates without the wiring. Filed as `MB-F-C5-MODEL-CONTEXT-WINDOW-WIRING-GAP` Tier 3 (§IV).

### WB3+WB4 — TileGridApp wiring

`WorkstationBridgeShape` extended with `onTileTokenUpdate?` (optional subscription, consistent with `onTileDetachClosed?` pattern). TileGridApp `useEffect` subscribes and maps over `sessions` to update `tokensUsed` on the matching entry. Unmatched sessionName is a no-op (no crash). Token update does NOT trigger `persistAndUpdate` — token count is transient display state, not layout state.

### Probe authoring fix

`probe-02-token-update.spec.tsx` initially imported `act` from `vitest`. `act` is not exported from `vitest`; it comes from `@testing-library/react`. Fixed at WB4 verification before commit. 4/4 tests pass after correction. Pattern: import `act` from `@testing-library/react`, not `vitest`.
